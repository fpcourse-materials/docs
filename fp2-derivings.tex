Earlier we said that everything programmers write is interpreters.
It turns out that many of them can be obtained automatically by reaching a new level of generality.
And code that does not have to be written --- should not be written.

As a rule, such a situation arises when the interpretation is fully determined by the description (the shape) of the type.
That is, by which data constructors are defined for it, with which fields, how those fields are named\ldots
Examples of such interpretations include serialisation into a particular format (e.g.\ json), structural equality, and so on.

The solution is for the language to support \vocab{structural polymorphism}~\cite[chapter 13]{maguire-types}, or \vocab{datatype-generic programming}, as it is sometimes called.

% todo we don't want to write code that doesn't need to be written

One can imagine a language in which datatype-generic programming is just ordinary programming~\cite{chapman2010gentle}.
To achieve this, one takes a language with dependent types together with a distinguished universe of descriptions \mintinline{haskell}|Desc|.
Concrete types are then obtained by applying an interpretation function \mintinline{haskell}|Desc -> Type|.
Thus, parametric polymorphism is embodied as generalisation over a type, while structural polymorphism is generalisation over its description.
